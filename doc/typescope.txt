1. INTRODUCTION                                      *typescope-introduction*

TypeScope resolves the function under the cursor through basedpyright, walks
the type of every parameter and of the return value, and draws the result as
a tree in a floating window.

Where a parameter is a dataclass, a Pydantic model, a TypedDict or a Protocol,
you get its fields — not just its name: >

    ▾ config   ServerConfig
      ├─ · host   str  "localhost"
      ├─ · port   int  8080
      ╰─ · debug  bool = False  True
    · timeout  float = 30.0  30.0
    ▾ returns  Response
      ├─ · status  int  200
      ╰─ · body    bytes
<
TypeScope performs no type inference of its own. Every type shown comes from
basedpyright; every field list is read out of the TreeSitter syntax tree.

2. REQUIREMENTS                                      *typescope-requirements*

These are hard requirements. Run |:checkhealth| typescope to see which are
missing.

Neovim 0.10+                The plugin refuses to load below this and notifies
                            once.

basedpyright                Attached to your Python buffers. This is the sole
                            source of type information. >
                                pip install basedpyright
<
TreeSitter python parser    Field extraction reads class bodies from the
                            syntax tree. >
                                :TSInstall python
<
Optional:

ollama                      LLM-generated example values. Off by default.
                            See |typescope-ollama-ram| before enabling.

curl                        Only needed when ollama is enabled.

3. SETUP                                                    *typescope-setup*

                                                        *typescope.setup()*
require("typescope").setup({opts})

{opts} is a table of overrides merged over the defaults in
|typescope-config|. Invalid values are rejected here, with a message naming
the offending key, rather than failing later during a paint.

Calling setup() more than once is safe. Turning a feature back OFF in a later
call really does remove its autocommands.

                                                    *typescope-setup-optional*
setup() is optional in the sense that the plugin loads and |:TypeScope| works
without it. But THREE features are wired only from setup(), so skipping it
silently disables them:

    - `prefetch`, the cursor-rest cache warming
    - warmstart, which kicks basedpyright's analysis on LspAttach
    - the `trigger = "hover"` auto-open autocommand

With lazy.nvim, `opts = {}` calls setup() for you. Configuring by hand, call
`require("typescope").setup({})` even with no overrides.

Install with lazy.nvim: >lua

    {
      "plongitudes/typescope.nvim",
      ft = "python",
      opts = {},
    }
<
==============================================================================
4. COMMANDS                                              *typescope-commands*

                                                                 *:TypeScope*
:TypeScope [subcommand]

    With no argument, toggles the float.

    toggle      Open the float, or close it if open. The default.

    open        Open the float. If it is already open, focus it, arming the
                tree mappings in |typescope-float-keys|.

    close       Close the float.

    hover       Draw the tree if the cursor is on a function; otherwise fall
                through to |vim.lsp.buf.hover()|. A drop-in replacement for
                |K| in Python buffers.

    spike       Preview the charset styles against built-in fixtures.
                See |typescope-styles|.

Subcommands tab-complete.

==============================================================================
5. MAPPINGS                                              *typescope-mappings*

No keys are mapped for you. Three |<Plug>| mappings are provided; bind them
rather than writing Lua callbacks: >lua

    vim.keymap.set("n", "<leader>ts", "<Plug>(TypeScopeToggle)")
    vim.keymap.set("n", "K", "<Plug>(TypeScopeHover)")
<
                                                    *<Plug>(TypeScopeToggle)*
                                                      *<Plug>(TypeScopeOpen)*
                                                     *<Plug>(TypeScopeHover)*
    <Plug>(TypeScopeToggle)     same as :TypeScope toggle
    <Plug>(TypeScopeOpen)       same as :TypeScope open
    <Plug>(TypeScopeHover)      same as :TypeScope hover

<Plug>(TypeScopeHover) is the one worth binding to |K|: on a function it
draws the tree, and on anything else it defers to the built-in hover, so it
adds no second key to remember.

6. INSIDE THE FLOAT                                   *typescope-float-keys*

These are active once the float has focus. All of them are configurable
through `keymaps` (|typescope-config|); the defaults are shown.

    <CR>        Expand or collapse the node under the cursor
    l           Expand the node under the cursor (no-op on a leaf)
    h           Collapse the node, or jump to its parent and collapse that
    L           Expand everything, including details
    H           Collapse everything
    j           Move to the next node (not the next line)
    k           Move to the previous node
    e           Toggle the example column
    E           Generate LLM examples for the visible tree (needs ollama)
    d           Docstring: jump into the full section, or collapse back
    q           Close
    <Esc>       Close
    ?           Toggle the help overlay

The `?` overlay is generated from your own `keymaps` table, so it stays
correct when you rebind anything. It replaces the view rather than appending
to it, because appended help routinely fell below the fold.

7. CONFIGURATION                                           *typescope-config*

Defaults in full: >lua

    require("typescope").setup({
      trigger = "manual",
      prefetch = true,
      depth = 2,
      show_examples = true,
      example_mode = "heuristic",

      insert_mode = {
        enabled = false,
        max_width = nil,
        max_detail_lines = 3,
      },

      ollama = {
        enabled = false,
        autostart = false,
        host = "localhost",
        port = 11434,
        model = "qwen2.5-coder:3b",
        timeout_ms = 8000,
        keep_alive = "5m",
      },

      ui = {
        style = "rounded",
        layout = "ledger",
        animations = true,
        align = "left",
        max_width = 0.5,
        max_height = 20,
        border = "rounded",
        docstring = "bottom",
        hint = true,
        focus = true,
      },

      highlights = {},

      keymaps = {
        expand = "<CR>",
        expand_node = "l",
        collapse_node = "h",
        expand_all = "L",
        collapse_all = "H",
        toggle_examples = "e",
        docstring = "d",
        llm_generate = "E",
        close = "q",
        help = "?",
      },
    })
<
                                                          *typescope-trigger*
trigger ~
    "manual"    Open only from a mapping or command. The default.
    "hover"     Also open on |CursorHold|. This auto-open never takes focus,
                whatever `ui.focus` is set to.

                                                         *typescope-prefetch*
prefetch ~
    Resolve the symbol under a resting cursor into the cache before any
    keypress, so the eventual open paints warm. No visible effect on its own.
    Requires setup() — see |typescope-setup-optional|.

                                                            *typescope-depth*
depth ~
    How far to walk nested types before an explicit expand is needed.
    Beyond it, a node is resolved lazily when you open it.

                                                        *typescope-ui-focus*
ui.focus ~
    true        An explicit open (K, :TypeScope) puts the cursor inside the
                float, so the tree keys are live immediately. The default.
    false       The momentary-hover convention: the float opens unfocused and
                any cursor movement dismisses it; a second K focuses it.

                                                    *typescope-ui-max-width*
ui.max_width ~
    Values of 1 or less are a fraction of the editor width; values above 1
    are absolute columns. `insert_mode.max_width` uses the same units and
    sizes only the typing surface, inheriting this when nil.

                                                          *typescope-ui-hint*
ui.hint ~
    A virtual-text "▸ typescope" marker on call lines that resolved, so you
    can tell at a glance where TypeScope has something to say.

8. LAYOUTS                                                *typescope-layouts*

Set `ui.layout`. Same data, different shapes.

ledger ~
    The default. One compact line per parameter (name, type, short default).
    The row under the cursor expands into a detail block — evaluated shape,
    example, origin — which follows as the cursor moves. L opens every row's
    detail block as a transient peek; the next cursor move ends it.

tree ~
    Flowing segments; type, default and example trail the name and wrap with
    a hanging indent when they run out of room.

                                                    *typescope-layout-table*
table ~
    DEPRECATED. It will be removed in the next release.

    True columns — name, mutability, type, default, example, origin — with
    alternating row backgrounds. It still works and still validates, but
    setting it emits a warning once per session. Use "ledger" or "tree".

9. INSERT MODE                                       *typescope-insert-mode*

`insert_mode.enabled = true` replaces your signature help with a typing
surface: every parameter name in one wrapped block with the active one
highlighted, a rule, then the active parameter's detail — type, evaluated
shape, default, example.

It follows textDocument/signatureHelp silently, overload changes included,
and repositions on every keystroke so it never covers the line you are typing
on nor the one below it. It has no mappings and is never focusable, by
design: no manual controls while you are mid-call.

Off by default while it bakes.

NOTE: turn off your existing signature help (blink.cmp, nvim-cmp, or core)
when enabling this, or two floats will contend for the same space.

                                              *typescope-max-detail-lines*
insert_mode.max_detail_lines ~
    Caps the DETAIL only, not the surface. The signature block above it
    wraps as far as it needs to keep every parameter name visible.

    Past the cap the shape — the one unbounded part — elides member by
    member rather than the detail growing, so a short union still shows in
    full while a 53-member Literal cannot eat the float. Raise it if you
    work with big Literals and want more of them at a glance.

10. EXAMPLES                                             *typescope-examples*

The example column shows a plausible value for each leaf.

                                                     *typescope-example-mode*
example_mode ~
    "heuristic"   Pattern-table values matched on name and type. No network,
                  no model, instant. Press E in the float to generate LLM
                  values on demand for what is visible. The default.
    "llm"         Generate through ollama when the float opens. Heuristics
                  show until the real values land, then swap in place.
    "none"        No example column.

                                                       *typescope-ollama-ram*
The RAM cost of ollama ~

`ollama.enabled` defaults to false for a reason worth stating plainly: a
loaded model is RESIDENT RAM, roughly 2GB for the default qwen2.5-coder:3b.

`keep_alive` controls how long the model stays resident after a request. The
default "5m" matches ollama's own, and on a small-RAM machine it is the ONLY
thing that reclaims the memory on a server TypeScope borrowed rather than
spawned. Raise it if you have the headroom and want warm E presses all
session.

`autostart = true` spawns `ollama serve` as a child process when the port
refuses connections; that child dies with Neovim, so the RAM returns on quit.
A server that is already running is never touched, and never shut down.

`timeout_ms` is a STALL timeout — how long the server may go completely
silent — not a total budget. The reply is streamed, so a slow machine simply
fills in more slowly and never trips it. Only a wedged server does.

11. STYLES                                                 *typescope-styles*

`ui.style` picks the charset: "unicode", "ascii", "minimal", "rounded". All
four are plain Unicode or ASCII — no Nerd Font glyphs — so any font works.

                                                           *typescope-spike*
To see them rather than guess: >

    :TypeScope spike
    :TypeScope spike ascii
<
This opens the real float, through the production render path, on built-in
fixtures: a dataclass, a nested Pydantic model, a TypedDict, and a Protocol
with an unresolved member. No LSP is involved, so it works in any buffer.

    <Tab>       next fixture
    <S-Tab>     previous fixture
    s           next style
    ?           help, including the keys above

12. HIGHLIGHTS                                         *typescope-highlights*

Every group links to something sensible in your colorscheme, so TypeScope
inherits your theme rather than overriding it.

    TypeScopeField              @variable
    TypeScopeParam              @variable.parameter
    TypeScopeType               @type
    TypeScopeDefault            @constant
    TypeScopeExample            Comment
    TypeScopeExamplePending     graded, dim to example color
    TypeScopeChrome             NonText
    TypeScopeKeyword            @keyword
    TypeScopeBadge              @attribute
    TypeScopeEvaluated          Comment
    TypeScopeHeader             @function
    TypeScopeHeaderDim          dimmed header
    TypeScopeDocstring          Comment
    TypeScopeUnresolved         DiagnosticWarn
    TypeScopeHint               Comment
    TypeScopeActive             LspSignatureActiveParameter
    TypeScopeTitle              FloatTitle
    TypeScopeRowOdd             CursorLine

Override through `highlights`: >lua

    require("typescope").setup({
      highlights = {
        TypeScopeExample = { fg = "#7aa2f7", italic = true },
      },
    })
<

13. HEALTH                                                 *typescope-health*
>
    :checkhealth typescope
<
Reports the Neovim version, the Python parser, and basedpyright (an active
client, or failing that the executable on PATH). When ollama is enabled it
also checks for curl and probes the server for reachability.

14. DEVELOPMENT                                       *typescope-development*
>
    ./tests/run.sh          all seven suites, headless
    stylua lua/ tests/      formatting
<
tests/run.sh adds your local site directory and nvim-treesitter to the
runtimepath, since the Python parser and its highlight queries are what the
extraction and injection paths need.

immediately after `stylua` can still report a diff. Run it twice.
