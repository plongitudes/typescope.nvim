1. INTRODUCTION                                      *typescope-introduction*

TypeScope asks a type checker what the symbol under the cursor is — a
function's parameters and return, a class's shape, a variable's type — and
draws the answer as an outline in a floating window, under the signature and
over an inspector for the row the cursor is on (|typescope-outline|).

Where a parameter is a dataclass, a Pydantic model, a TypedDict, a NamedTuple,
an Enum, a Protocol or a plain class with annotated attributes, you get its
fields — not just its name: >

    ▾ config   ServerConfig
      ├─ · host   str  "localhost"
      ├─ · port   int  8080
      ╰─ · debug  bool = False  True
    · timeout  float = 30.0  30.0
    ▾ returns  Response
      ├─ · status  int  200
      ╰─ · body    bytes
<
TypeScope performs no type inference of its own. Every type shown comes from
the oracle: a small binary wrapping the pyrefly checker, run beside your
Python language server as a second LSP server that answers one request.
Generics arrive specialized, an unannotated name shows the checker's
inference (drawn ≈), a narrowed variable shows its narrowed type.

2. REQUIREMENTS                                      *typescope-requirements*

These are hard requirements. Run |:checkhealth| typescope to see which are
missing.

Neovim 0.11+                The plugin refuses to load below this and notifies
                            once.

typescope-oracle            The binary every type comes from. With the
                            default `oracle.download = true` the plugin
                            fetches the release build for your platform
                            (Apple Silicon macOS, or Linux on x86_64 or
                            arm64) into
                            stdpath("data")/typescope/oracle/<release>/
                            the first time a Python buffer opens, verifies
                            it against the release's SHA256SUMS before
                            running it, and says so once. A plugin update
                            that pins a different release fetches that one
                            and removes the old. Needs curl, and sha256sum
                            or shasum for the check. To skip the
                            download, build it (|typescope-development|)
                            and set `oracle.path`, or set
                            `oracle.download = false` and place the binary
                            at the path |:checkhealth| names. Intel Macs
                            have no release build: build it and set
                            `oracle.path`.

TreeSitter python parser    The float's highlighting and the call-site
                            questions (is the cursor on a call, what was
                            written in it) read the syntax tree. >
                                :TSInstall python
<
Recommended:

basedpyright                Attached to your Python buffers. No longer
                            needed to resolve types; used for signatureHelp
                            (the active parameter as you type) and as the
                            hover <Plug>(TypeScopeHover) falls back to. Any
                            Python server with those capabilities works.

Optional:

ollama                      LLM-generated example values. Off by default.
                            See |typescope-ollama-ram| before enabling.

3. SETUP                                                    *typescope-setup*

                                                        *typescope.setup()*
require("typescope").setup({opts})

{opts} is a table of overrides merged over the defaults in
|typescope-config|. Invalid values are rejected here, with a message naming
the offending key, rather than failing later during a paint.

Calling setup() more than once is safe. Turning a feature back OFF in a later
call really does remove its autocommands.

                                                    *typescope-setup-optional*
setup() is optional in the sense that the plugin loads and |:TypeScope| works
without it. But THREE features are wired only from setup(), so skipping it
silently disables them:

    - `prefetch`, the cursor-rest cache warming
    - warmstart, which kicks basedpyright's analysis on LspAttach
    - the `trigger = "hover"` auto-open autocommand

With lazy.nvim, `opts = {}` calls setup() for you. Configuring by hand, call
`require("typescope").setup({})` even with no overrides.

Install with lazy.nvim: >lua

    {
      "plongitudes/typescope.nvim",
      ft = "python",
      opts = {},
    }
<
==============================================================================
4. COMMANDS                                              *typescope-commands*

                                                                 *:TypeScope*
:TypeScope [subcommand]

    With no argument, toggles the float.

    toggle      Open the float, or close it if open. The default.

    open        Open the float. If it is already open, focus it, arming the
                tree mappings in |typescope-float-keys|.

    close       Close the float.

    hover       Draw the tree if the cursor is on a function; otherwise fall
                through to |vim.lsp.buf.hover()|. A drop-in replacement for
                |K| in Python buffers.

Subcommands tab-complete.

==============================================================================
5. MAPPINGS                                              *typescope-mappings*

No keys are mapped for you. Three |<Plug>| mappings are provided; bind them
rather than writing Lua callbacks: >lua

    vim.keymap.set("n", "<leader>ts", "<Plug>(TypeScopeToggle)")
    vim.keymap.set("n", "K", "<Plug>(TypeScopeHover)")
<
                                                    *<Plug>(TypeScopeToggle)*
                                                      *<Plug>(TypeScopeOpen)*
                                                     *<Plug>(TypeScopeHover)*
    <Plug>(TypeScopeToggle)     same as :TypeScope toggle
    <Plug>(TypeScopeOpen)       same as :TypeScope open
    <Plug>(TypeScopeHover)      same as :TypeScope hover

<Plug>(TypeScopeHover) is the one worth binding to |K|: on a function it
draws the tree, and on anything else it defers to the built-in hover, so it
adds no second key to remember.

6. INSIDE THE FLOAT                                   *typescope-float-keys*

These are active once the float has focus. All of them are configurable
through `keymaps` (|typescope-config|); the defaults are shown.

    <CR>        Expand or collapse the node under the cursor
    l           Open one more level under the node (a collapsed node opens;
                an open one reveals its next level down)
    h           Collapse the node, or jump to its parent and collapse that
    H           Collapse everything
    j           Move to the next node (not the next line)
    k           Move to the previous node
    e           Ask the model for this row's example, and its neighbours'
                (needs ollama)
    d           Docstring: show it in the loupe in place of the inspector,
                or go back to the inspector
    <C-d>       Scroll the docstring view down (in the outline otherwise)
    <C-u>       Scroll the docstring view up (in the outline otherwise)
    q           Close, from any view
    <Esc>       Close, from any view
    ?           Open the help view, or close it

                                                       *typescope-help-view*
The help view is generated from your own `keymaps` table, so it stays correct
when you rebind anything. It is drawn over the frame, titled
`typescope help`, and the panes under it keep their sizes. It grows away from
the line of code at the cursor: when the frame sits below the cursor it grows
up to the frame's top and then down past its bottom; when the frame sits
above, it grows up past the frame's top. While it shows, the row keys
(<CR>, l, h, H, e, j, k, <C-d>, <C-u>) do nothing, so the outline cannot move
under it. `?` again returns to whatever the loupe showed before; `d` goes
straight to the docstring view.

7. CONFIGURATION                                           *typescope-config*

Defaults in full: >lua

    require("typescope").setup({
      trigger = "manual",
      prefetch = true,
      depth = 2,
      show_examples = true,
      example_mode = "heuristic",

      insert_mode = {
        enabled = false,
        max_width = nil,
        max_detail_lines = 3,
      },
      oracle = {
        path = nil,          -- an explicit binary; nil = the downloaded one
        download = true,     -- fetch the release build when none is found
      },

      ollama = {
        enabled = false,
        autostart = false,
        host = "localhost",
        port = 11434,
        model = "qwen2.5-coder:3b",
        timeout_ms = 8000,
        keep_alive = "5m",
      },

      ui = {
        style = "rounded",
        animations = true,
        max_width = 0.5,
        max_height = 20,
        min_height = { header = 1, outline = 5, inspector = 1 },
        border = "rounded",
        docstring = true,
        hint = true,
        focus = true,
      },

      highlights = {},

      keymaps = {
        expand = "<CR>",
        expand_node = "l",
        collapse_node = "h",
        collapse_all = "H",
        docstring = "d",
        llm_generate = "e",
        close = "q",
        help = "?",
      },
    })
<
                                                          *typescope-trigger*
trigger ~
    "manual"    Open only from a mapping or command. The default.
    "hover"     Also open on |CursorHold|. This auto-open never takes focus,
                whatever `ui.focus` is set to.

                                                         *typescope-prefetch*
prefetch ~
    Resolve the symbol under a resting cursor into the cache before any
    keypress, so the eventual open paints warm. No visible effect on its own.
    Requires setup() — see |typescope-setup-optional|.

                                                            *typescope-depth*
depth ~
    How far to walk nested types before an explicit expand is needed.
    Beyond it, a node is resolved lazily when you open it.

                                                        *typescope-ui-focus*
ui.focus ~
    true        An explicit open (K, :TypeScope) puts the cursor inside the
                float, so the tree keys are live immediately. The default.
    false       The momentary-hover convention: the float opens unfocused and
                any cursor movement dismisses it; a second K focuses it.

                                                    *typescope-ui-max-width*
ui.max_width ~
    Values of 1 or less are a fraction of the editor width; values above 1
    are absolute columns. `insert_mode.max_width` uses the same units and
    sizes only the typing surface, inheriting this when nil.

                                                   *typescope-ui-max-height*
ui.max_height ~
    The content rows the frame's panes share. Borders and seams are extra,
    so the float on screen is taller than this by its chrome.

                                                   *typescope-ui-min-height*
ui.min_height ~
    Default `{ header = 1, outline = 5, inspector = 1 }`. The rows each pane
    of the frame keeps before the rest of `ui.max_height` is shared out. A
    pane with less content than its minimum shrinks to fit it, so a
    one-parameter function does not get five outline rows. Leftover rows go
    to the header until its signature is fully wrapped, then to the
    inspector up to five rows, then to the outline. On a screen too short for
    the minimums, the outline, then the header, then the inspector give way,
    down to a row each; the float still opens with as few as three rows.

                                                          *typescope-ui-hint*
ui.hint ~
    A virtual-text "▸ typescope" marker on call lines that resolved, so you
    can tell at a glance where TypeScope has something to say.

                                                        *typescope-layouts*
8. THE OUTLINE                                            *typescope-outline*

The float is a frame of three panes stacked on one side of the cursor: the
header, the outline, and the loupe. Each seam between two panes is drawn as
the upper pane's full bottom border followed by the lower pane's full top
border, in your `ui.border` style, because the panes do separate jobs. The
frame opens below the cursor, or above it when there is more room there, and
keeps that side until it closes. Its left edge sits at the cursor's column,
slid left only as far as the screen edge requires. The frame's bottom border
carries `? help` at its right end, whichever view is showing.

                                                       *typescope-header*
The header is the signature, wrapped onto as many rows as it needs. It stays
put while the outline scrolls. On an overloaded callable it shows the overload
group the cursor is in, and its bottom border carries that group's `[i/n]`,
with `✓` beside it when the group is the matched overload (the one the call at
the cursor resolves to). `[i/n]` keeps its column whether or not `✓` shows.
The header's height is fixed at the tallest group's wrapped signature, so the
outline never shifts as you cross groups; a signature that cannot fit is cut
from the middle, keeping its start and its return type.

                                                      *typescope-outline-rows*
The outline is one compact row per parameter (name, type, short default),
with fields, members and the return type beneath. An overload group's row
keeps its own `[i/n]`, so group boundaries show as you scroll.

                                                         *typescope-loupe*
The loupe, the bottom pane, shows one of two views:

    inspector       Everything about the outline row under the cursor: its
                    whole type, evaluated shape, full default, example,
                    origin. The rows never move with the cursor; only the
                    inspector changes.
    docstring view  The callable's whole docstring, shown in place of the
                    inspector by d (d again goes back). The cursor stays in
                    the outline, and the view scrolls to the hovered
                    parameter's `:param` section as you move; <C-d> and <C-u>
                    scroll it by hand. It grows the frame toward
                    `ui.max_height`, away from the line of code at the
                    cursor, then squashes the outline and then the header to
                    their minimums (the outline keeps its cursor row in
                    view). Going back restores every pane's size.

                                                      *typescope-docstring*
ui.docstring ~
    true (the default): d shows the docstring view. false turns it off.

It used to be one of several layouts. "table" was removed in 0.2.0 and
"tree" in 0.4.0; a `ui.layout` or `ui.align` left in your setup is ignored
with a one-time warning.

9. INSERT MODE                                       *typescope-insert-mode*

`insert_mode.enabled = true` replaces your signature help with a typing
surface: every parameter name in one wrapped block with the active one
highlighted, a rule, then the active parameter's detail — type, evaluated
shape, default, example.

It follows textDocument/signatureHelp silently, overload changes included,
and repositions on every keystroke so it never covers the line you are typing
on nor the one below it. It has no mappings and is never focusable, by
design: no manual controls while you are mid-call.

Off by default while it bakes.

NOTE: turn off your existing signature help (blink.cmp, nvim-cmp, or core)
when enabling this, or two floats will contend for the same space.

                                              *typescope-max-detail-lines*
insert_mode.max_detail_lines ~
    Caps the DETAIL only, not the surface. The signature block above it
    wraps as far as it needs to keep every parameter name visible.

    Past the cap the shape — the one unbounded part — elides member by
    member rather than the detail growing, so a short union still shows in
    full while a 53-member Literal cannot eat the float. Raise it if you
    work with big Literals and want more of them at a glance.

10. EXAMPLES                                             *typescope-examples*

The inspector shows a plausible example value for each leaf.

                                                     *typescope-example-mode*
example_mode ~
    "heuristic"   Pattern-table values matched on name and type. No network,
                  no model, instant. Press e on a row to ask the model
                  for its example on demand. The default.
    "llm"         Generate through ollama automatically, for the inspector's
                  row and its nearest neighbours as the cursor reaches them,
                  one batch at a time. Heuristics show until the real values
                  land, then swap in place.
    "none"        No examples.

                                                       *typescope-ollama-ram*
The RAM cost of ollama ~

`ollama.enabled` defaults to false for a reason worth stating plainly: a
loaded model is RESIDENT RAM, roughly 2GB for the default qwen2.5-coder:3b.

`keep_alive` controls how long the model stays resident after a request. The
default "5m" matches ollama's own, and on a small-RAM machine it is the ONLY
thing that reclaims the memory on a server TypeScope borrowed rather than
spawned. Raise it if you have the headroom and want warm e presses all
session.

`autostart = true` spawns `ollama serve` as a child process when the port
refuses connections; that child dies with Neovim, so the RAM returns on quit.
A server that is already running is never touched, and never shut down.

`timeout_ms` is a STALL timeout — how long the server may go completely
silent — not a total budget. The reply is streamed, so a slow machine simply
fills in more slowly and never trips it. Only a wedged server does.

11. STYLES                                                 *typescope-styles*

`ui.style` picks the charset: "unicode", "ascii", "minimal", "rounded". All
four are plain Unicode or ASCII — no Nerd Font glyphs — so any font works.

    rounded     The default: box-drawing tree lines, with a rounded corner
                on the last child.
    unicode     The same, with a square corner on the last child.
    ascii       Tree lines drawn with + - | \ for SSH sessions and
                terminals with a partial font.
    minimal     No tree lines; indentation only.

13. HEALTH                                                 *typescope-health*
>
    :checkhealth typescope
<
Reports the Neovim version, the Python parser, basedpyright (an active
client, or failing that the executable on PATH), and the oracle: where the
binary is, its version and protocol, whether a client is attached, and why a
download failed if one did. When ollama is enabled it also checks for curl
and probes the server for reachability.

14. DEVELOPMENT                                       *typescope-development*
>
    scripts/build-oracle.sh             the oracle, debug build (Rust)
    scripts/build-oracle.sh --release   the binary that ships
    (cd oracle && cargo test)           the oracle's own tests
    ./tests/run.sh                      every Lua suite, headless
    stylua lua/ tests/                  formatting
<
The oracle lives in oracle/: a Rust crate over pyrefly, pinned to the
commit in oracle/pyrefly.rev. The build script fetches that commit
(shallow), applies the one small patch in oracle/patches/ and builds. design/oracle.md records the contract and the
decisions behind it.

tests/run.sh adds your local site directory and nvim-treesitter to the
runtimepath for the Python parser and its highlight queries. The suites that
drive the real oracle skip themselves when oracle/target/debug/ has no
binary, so the pure-Lua suites need no Rust toolchain.

NOTE: stylua needs two passes to converge on this tree, so `stylua --check`
immediately after `stylua` can still report a diff. Run it twice.
